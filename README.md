# 朝食やさいチャレンジ・保護者版

元の `naoki6043/yasai-challenge` を履歴付きでコピーした改修版です。
基準コミット: `b46535ee55a17cd7d4f4dd9f823086e05e12a74f`。
元のリポジトリ・公開サイト・管理シート・Apps Scriptの設定は変更していません。

## 変更点

- ホームの野菜10種類・各3料理・既存の料理の並び順と写真を維持。
- 野菜名と同じ枠の中に、栄養学的特徴を1文表示。
- 学ぶ、クイズ、学年選択を削除。
- 日付／調理参加3択／摂取量5択を、同一料理・同一日でも繰り返し記録。
- 料理別の履歴と全体の履歴、月・料理による絞り込み、編集・削除。
- 利用者写真の登録機能なし。完成写真・工程写真・材料・作り方・栄養情報・アレルギー情報を維持。

## データ保存と既存版の保護

記録はこの端末のlocalStorageの `yasai-parents-v1-state` に保存します。
元アプリの `awveg-v6-` キーは読み書きせず、既存の匿名IDも流用しません。
新規ID・記録ID・変更イベントIDを分けています。0（食べなかった）も有効です。
保存に失敗した場合は完了表示を出しません。削除は対象の1件だけです。
端末間同期・バックアップ復元は未実装です。ブラウザデータを消すと記録も失われます。

旧研究用の行動ログAPIへ、新形式の記録は送りません。
旧URLは `original-config.js.txt` と `LEGACY_ACTION_LOG_API_URL` に保存しています。
`ACTION_LOG_API_URL` は、新形式（record_created/updated/deleted、record_id、event_id）に対応する
保護者版専用の送信先を確認後に設定してください。送信先未設定でも端末内の記録は使えます。
失敗した変更イベントは再送用キューに保持します。受信側はevent_idで重複を排除し、
record_idを使って編集・削除を反映する必要があります。

Service Workerはこのコピーのパスに限定し、元アプリのキャッシュを削除しません。

## Google Sheets / Apps Script / content.json

保護者版管理シート:
https://docs.google.com/spreadsheets/d/1mvyWp_CxPcO4_QRbY8bqiXoEWW5XxMpp9ApaH4XdzvM/edit

元の管理シートをそのままコピーしています。既存のレシピ・写真管理等は維持。
追加した「野菜情報」シートは1野菜1行で、C列「栄養学的特徴」を編集します。
元シートの編集は保護者版へ自動反映しません。以後はこのコピーで管理してください。

追加公開処理は `GoogleAppsScript_保護者版公開.gs`。
コピーしたシートのApps Scriptにこのファイルを追加し、
スクリプトプロパティ `PARENTS_GITHUB_TOKEN` を設定して `publishParentsContent` を実行します。
トークンは新リポジトリだけのContents書き込み権限に限定し、ソース・config.jsへ書きません。
これは管理者側の初回設定が必要です。この改修では未接続のため、Sheetsからの自動更新はまだ有効ではありません。

**コピー元から引き継いだ既存の公開メニューや関数は実行しないでください。**
コピーされた古いApps Scriptが元リポジトリを向く可能性があるため、
保護者版専用の上記関数を使います。追加処理はシートID・書き込み先を固定して元版を保護します。
公開状態が「公開」のR01〜R30だけを検証し、野菜情報を結合して新リポジトリのcontent.jsonに書き込みます。
入力者・確認者・DriveID・行動ログ・教材・クイズは出力しません。
検証エラー時は既存content.jsonを変更しません。GitHubのshaを使い同時更新の上書きを防ぎます。

起動時は既存版と同じく、このリポジトリ自身のcontent.jsonを取得します。
config.jsのRECIPE_API_URLは元の設定を保管していますが、現行版と同様に起動時の直接取得には使いません。
今回、元APIの匿名HTTP取得はJSONではなくHTML応答でした。元デプロイは変更していません。

栄養文は食品に含まれる栄養素の一般的な説明として初期登録しています。
実際の料理の栄養値・注意事項は従来どおり料理詳細を参照します。
